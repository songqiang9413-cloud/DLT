# DLT 项目（部署到 Base 主网）

ERC20 代币 DLT + 每小时一期的链上彩票 + 国库 ETH 自动做市。

## Live deployment (Base mainnet)

- DLT token: `0xe9c553454B48C71537AC9Dddae495D9181E3990f`
- Lottery: `0x88B31E49Fd48108c132Aa0891DBd74caA5199A68`
- Uniswap V2 pair: `0xdE787eDb5A87a0B299154fF6504808367Ed93f59`
- Admin: `0x6DFb0fA0873fBC4038764f7c902A86ebE1ECe561`
- Team: `0x45F3aE8A36A1bC263AC5543d6876Dc37542F1785`
- Source: https://github.com/songqiang9413-cloud/DLT

- **DLT 代币合约：零 owner、零 admin、无暂停、无提币、不可升级。**
- **彩票合约：零 owner；只有一个不可转让的限权管理员，管理员只能提案修改/撤回团队收款地址，链上公示 24 小时后才生效。**
- 所有业务参数写死，没有修改赔率、注价、周期、奖池比例的 set 函数。

## 二、部署前准备

### 1. 部署钱包

准备一个钱包，里面放少量 Base 链上的 ETH。

- 部署总消耗约 **234 万 gas**，Base 上实际花费一般在 **1 美元左右**（主要是把合约代码传到 L1 的数据费）。
- 建议至少放 **0.005 ETH**：够部署 + 建池（0.002 ETH）+ 留余量。

### 2. 管理员钱包（重要）

正式上线需要一个管理员，但它的权力被严格限制为：

- 只能提案修改（或撤回提案）**团队收款地址**；
- 提案后必须等 **24 小时**；
- 24 小时后**任何人**都可以调用 `activateTeam()` 让新地址生效；
- 不能暂停、不能提币、不能增发、不能改注价/周期/赔率、不能换管理员、不能升级。

建议用一个**独立的长期钱包**做管理员，不要和团队收款地址共用一把私钥。否则收款私钥泄露时，管理员权限也会一起泄露，24 小时延迟的保护会大打折扣。

管理员地址在部署时写死，之后**不可更换**。这个钱包的私钥必须长期保存；丢了就再也不能改团队收款地址（系统本身仍会按当前地址继续运行）。

### 3. 设置环境变量

```powershell
$env:DEPLOYER_KEY="0x你的部署私钥"
$env:ADMIN_ADDRESS="0x你的长期管理员钱包地址"   # 推荐设置
```

- `DEPLOYER_KEY`：只在本机使用，永远不要发给任何人。
- `ADMIN_ADDRESS`：不设置时默认等于部署钱包，部署脚本会打印警告。
- 每次新开一个 PowerShell 窗口都要重新设置一次。

## 三、部署（3 步）

```powershell
cd F:\SQ001\100DLT
$env:DEPLOYER_KEY="0x你的部署私钥"
$env:ADMIN_ADDRESS="0x你的长期管理员钱包地址"

# 1) 部署
npx hardhat run scripts/deploy.js --network base

# 2) 建初始交易池（花 0.002 ETH，永久锁死，想让人能买卖就必须做）
npx hardhat run scripts/createInitialPool.js --network base

# 3) 查看状态
npx hardhat run scripts/status.js --network base
```

部署完会打印两个地址，**务必抄下来保存**：

- **Lottery 合约地址** —— 玩家投注、开奖的地方；
- **DLT 代币合约地址** —— 玩家添加代币、买卖 DLT 时用的地址。

部署脚本会自动做 **20 项参数自检**，全部显示 `[OK]` 才算部署正确。自检包括：管理员地址、初始团队地址、24 小时延迟、DLT 不再保存团队地址、激励 10 + 20、已删除 100 DLT 门槛等。

> ⚠️ 私钥、助记词永远不要发给任何人（包括我）。部署交易只需要私钥在本机签名。

## 四、上线后系统怎么运转

### 1. 玩家怎么获得 DLT

两种方式：

- **铸币**：直接给 **DLT 代币合约地址**转 ETH，必须是 **0.001 ETH 的整数倍**（0.001 ETH = 20 DLT，0.01 ETH = 200 DLT）。
  - 其中 **99% 的 ETH 立刻打进黑洞销毁**，**1% 留在合约里当国库**（以后只用于自动加池）。
- **买**：在 Uniswap 上用 ETH 买 DLT（前提是池子已经建好）。

### 2. 玩家怎么投注

1. 先在 DLT 合约上给**彩票合约地址**授权（approve）足够的 DLT。
2. 打开 Basescan 上彩票合约页面 → `Contract` → `Write Contract` → 连接钱包 → 调用 `bet(注数)`。
   - 每注 **2 DLT**，一次最多 **200 注**；
   - 投的 DLT **立刻全部销毁**，投 N 注就等于占 N 个抽奖号。
3. 期号 = 当前 UNIX 时间 ÷ 3600（整点对齐）。**当期的注下一整点封盘**。

### 3. 谁负责开奖（任何人都可以，包括你）

每小时分两步，**任何人都能调用**：

| 步骤 | 什么时候调 | 调用者奖励 |
| --- | --- | --- |
| `requestDraw(期号)` | 该期结束后（下一个整点起） | 10 DLT |
| `executeDraw(期号)` | 封盘后再等 **200 个区块**（Base 上约 7 分钟） | 20 DLT |

规则细节：

- **只要当期至少有 1 注，就发激励**（不再有 100 DLT 门槛）；空期不发、不铸造、直接标记结束。
- 每期请求激励只发一次；执行窗口过期后重新请求，不再发 10 DLT，但仍可拿执行时的 20 DLT。
- 随机数用的是“请求区块 + 200”的区块哈希，**请求的时候谁都算不出中奖者**，所以没法挑时机作弊。
- 如果 200 个区块后没人来执行（窗口 255 个区块），请求作废，任何人都可以**重新请求**。
- 某一期完全没人投注 → 直接标记结束，不铸造、不报错。

> **为什么 1 注也发 30 DLT？**
> 这是为了保证早期每一期都有人愿意开奖。代价是：自己投 1 注（2 DLT）+ 自己 request + 自己 execute，
> 推广期能拿 1.47 DLT 奖金 + 30 DLT 激励，净赚约 **29.47 DLT**；推广期结束后净赚约 **28.98 DLT**。
> 这是明确接受的“保证开奖成本”，也是新增铸币。当前合约不可改；如果以后想降低，只能部署新版本。

### 4. 奖金怎么分

当期投注总量（已经全部销毁的那部分）的：

- **49%** 铸给中奖者；
- **1%** 铸给**当前团队收款地址**；
- 剩下的 **50% 永久销毁**（这是 DLT 的净通缩来源）。

**🎁 上线起前 720 期（约 30 天）另有“基础奖池”补贴：**

```
基础奖池 = min(1,000 DLT, 当期真实投注量的一半)
可分配奖池 = 当期投注量 + 基础奖池
```

- 大家投 100 DLT → 基础奖池补 50 → 按 150 DLT 分：中奖者 **73.5 DLT**（原来只有 49）。
- 大家投 10,000 DLT → 基础奖池补满 1,000（封顶）→ 中奖者 5,390 DLT。
- 没人投注 → 不补、不开奖、不报错。
- 第 721 期起自动恢复原规则，任何人都改不了。

> 基础奖池补“一半”而不是全额，是为了控制早期增发；但注意，**开奖激励是另外固定新增的**，
> 所以小额期仍然可能是净增发。详见下面“会不会通胀”。

### 5. 团队收款地址怎么改（限权管理员）

初始团队地址写死在 `Lottery.sol` 的 `INITIAL_TEAM`：

```
0x45F3aE8A36A1bC263AC5543d6876Dc37542F1785
```

以后要改，只能走这三步：

1. **管理员提案**：调用 `proposeTeam(新地址)`。
   - 只允许管理员调用；
   - 新地址不能是零地址，也不能等于当前团队地址；
   - 会发出链上事件 `TeamChangeProposed`，这就是“全网公布”的公开凭证；
   - 提案不会立即生效，`team` 仍然是旧地址。
2. **等 24 小时**：`teamChangeEffectiveAt` 是公开可查的生效时间。
3. **任何人激活**：24 小时后调用 `activateTeam()`，新地址才真正生效，并发出 `TeamChanged` 事件。

补充规则：

- 管理员可以重新提案；新提案会覆盖旧提案，并**重新开始 24 小时计时**。
- 管理员也可以用 `cancelTeamChange()` 撤回尚未生效的提案（防手滑）；撤回后提案清零、`team` 不变，之后任何人也不能再激活它。
- 没有“立即改地址”的后门，也没有暂停、提币、增发、改参数、换管理员的函数。
- 管理员地址不可转让；丢了就再也不能改团队地址。
- 开奖时按**执行那一刻的 `team`** 发 1%；如果新地址在开奖前生效，1% 就发给新地址。
- 新地址必须是能接收/持有 ERC20 的地址；如果是合约钱包，请先确认它能正常收 DLT。

### 6. 自动做市（国库 ETH 变池子深度）

- 国库累积到 **0.01 ETH** 之后，**任何人都可以**调用 `autoAddLiquidity()`。
- 单次最多动用：`min(0.5 ETH、池子 ETH 余额的 10%、国库余额)`。
- 合约会按池子当前价格铸出对应数量的 DLT，和国库 ETH 一起注入池子，**LP 永久锁死在合约里，没有任何取出函数**。
- 池子还不存在时，这一步会顺便把池子建起来（按官方价 1 ETH = 20000 DLT）。

## 六、常见问题

**问：部署完我有什么特权？**

答：分两层：

- **DLT 代币合约：没有任何特权。** 没有 owner、没有 admin、没有暂停、没有提币、没有参数修改函数。
- **彩票合约：有一个管理员，但只能提案修改（或撤回）团队收款地址，且必须等 24 小时。** 不能暂停、不能提币、不能增发、不能改注价/周期/奖池比例、不能换管理员、不能升级。

**问：团队地址以后能换吗？**

答：能，但只能通过管理员 `proposeTeam` + 24 小时公示 + 任何人 `activateTeam`。没有立即修改的办法。

**问：管理员能不能偷国库或 LP？**

答：不能。国库 ETH 只有 `autoAddLiquidity()` 一个出口，LP 永久锁在 DLT 合约里；管理员没有提币、没有转账、没有升级权限。管理员唯一能做的，是在 24 小时公开预告后把**未来的团队 1%** 改到一个新地址。过去的余额和奖池都动不了。

**问：DLT 能换回 ETH 吗？**

答：链上没有赎回功能（没有兑换函数）。想变现只能在 Uniswap 池子里卖给别的买家。

**问：如果一直没人开奖会怎样？**

答：奖金不会作废。那一期会一直停在“已封盘/待开奖”状态，谁先来开都能开出来，奖金按当时的投注总量发。超过 255 个区块后需要重新请求一次。

**问：没人调用激励怎么办？**

答：现在只要当期有 1 注就发 10 + 20 DLT，不需要等池子到 100 DLT。空期则只需要 `requestDraw` 直接关闭，不需要 `executeDraw`。

**问：铸币会不会无限通胀？**

答：分两层看。

- **投注层**：投注 100% 销毁，开奖只铸回可分配奖池的 50%。正常时期（无推广补贴）投注层每期净销毁 = 投注量的 50%。
- **激励层**：每个非空期最多新增 10 + 20 = 30 DLT，一天最多 720 DLT。这是固定增发，不会因为奖池变大而变多。

把两层合起来（B = 当期真实投注量）：

- 推广期内、B ≤ 2000 DLT：净供应变化 ≈ `-0.25B + 30`，B > 120 DLT 时才净通缩；B ≤ 120 DLT 时小额净增发。
- 第 721 期起：净供应变化 = `-0.5B + 30`，B > 60 DLT 时才净通缩；B ≤ 60 DLT 时小额净增发。
- 推广期内、B > 2000 DLT（基础奖池封顶 1,000）：净供应变化 ≈ `-0.5B + 530`，B > 1,060 DLT 时净通缩。

所以：**前期人少时会靠固定激励把币发出去，这是为了冷启动；投注量上来后，销毁会超过激励。** 当前合约参数不可改，如果以后要调激励，只能部署新版本。

## 七、安全提醒

- 私钥只放在本机环境变量里，不要写进任何文件、不要发给任何人。
- **管理员钱包和团队收款钱包最好分开。** 如果两把是同一把，私钥泄露时“24 小时后还能改地址”的保护会大打折扣。
- 管理员地址不可更换；请用长期保存的钱包，不要用一次性热钱包。
- 部署前把 `contracts/Lottery.sol` 里的 `INITIAL_TEAM` 再核对一遍；部署脚本也会自检。
- 团队地址必须能接收 ERC20；如果换成合约钱包，先确认它支持 DLT。
- 合约不可升级：上线后发现任何问题，只能重新部署新合约。
